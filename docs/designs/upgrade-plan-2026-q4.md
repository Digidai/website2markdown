# md.genedai.me 升级计划（2026 Q4 – 2027 Q1）

生成于 2026-10-31。依据：生产 D1 数据（access_events / conversion_log 自 2026-09-28 起，usage_daily 自 2026-04 起）、代码现状（commit b1e41b8）、2026-10-31 市场调研。

## 1. 一句话判断

工程已经是"好产品"的水准（756 测试、观测完善、微信抓取质量领先），但商业闭环不存在：**没有付费入口，没有分发渠道，没有聚焦的目标用户**。下一阶段的工作重心应从"加功能"切换为"把已经在用的人变成付费用户"。

## 3. 市场位置

- 通用 URL→Markdown 已是红海且价格崩塌：Firecrawl（$75M B 轮，$0.75–3.8/千页）、Jina（被 Elastic 收购，约 $0.25/千页）、Exa/Tavily（$1/千页）、markdown.new 与 Cloudflare Markdown for Agents（免费）。**在通用场景上和他们竞争没有胜算。**
- 差异化是真实的：2026-10-31 同一篇微信文章，Jina 被验证码拦截、markdown.new 返回"环境异常"，我们拿到完整 3,437 字正文。
- 中文赛道最知名的 wechat-article-exporter（1.3 万 star）于 2026-07-29 关闭公开 API 和会员购买——**供给侧出现空缺**，但也提示合规/风控风险。
- 中文用户的顾虑是"文章经过别人的服务器"和"登录墙/风控"；付费习惯弱，B 端（RAG、Agent、舆情/政策监控）比 C 端更能付费。
- Smithery 于 2026-10-31 关停托管；官方 MCP Registry 与 Dify Marketplace（Firecrawl 是其默认网页导入器）是当前最值得进入的渠道。

**定位建议：** 从"Convert any URL to Markdown"改为 **"中文互联网内容的可靠 Markdown 接口——给 AI Agent 和知识库用"**（微信、知乎、飞书、政府/公告站）。通用网页作为附带能力，不作为卖点。

## 4. 目标用户（按付费意愿排序）

1. **中文内容管道型 B 端**：RAG/知识库构建者、舆情/政策监控、投研信息采集（证据：CN/SG 微信 bot、用户 A）。买的是成功率和稳定性。
2. **AI Agent / 工具开发者**：通过 MCP、Dify、n8n 调用（证据：调研中 Firecrawl 通过 Dify 默认入口获客）。
3. **个人知识管理用户**（Obsidian/思源/NotebookLM）：量大、付费弱，作为口碑和 SEO 来源，用扩展/剪藏服务。

## 5. 升级计划

### Phase 1（2 周）：打通变现闭环 —— 最高优先级

| # | 事项 | 说明 |
|---|---|---|
| 1.1 | 定价页 + 升级入口 | 落地页、portal、429/401/微信失败响应里都给出升级路径。建议：Free 1,000 credits；Starter ¥49/$9 每月 1 万；Pro ¥199/$29 每月 5 万；超量按量计费；团队/企业询价 |
| 1.2 | 支付接入 | 海外 Paddle（schema 已在）；国内补微信/支付宝渠道（如 Lemon Squeezy 不支持则考虑 PingPong/易支付类聚合或手动发票），先支持"年付/充值包"降低实现成本 |
| 1.3 | 失败响应引导 | 匿名微信"只拿到页面壳"的 502 改为明确提示"此页面需要浏览器渲染，免费注册 key 即可"，并附 portal 链接；`X-Upgrade-Url` 头便于程序化调用方看到 |
| 1.4 | 匿名大户转化 | 对持续调用的匿名客户端（按 UA/ASN 聚类）返回带联系方式的提示头；对 numisbids 这类单一来源批量抓取按 host 限额 |
| 1.5 | 联系留存用户 | 主动联系用户 A、B（有邮箱）：访谈需求、免费升级 Pro 换反馈与案例 |

**完成标志：** 第一个真实付费用户；匿名微信失败中带升级提示的比例 100%。

### Phase 2（第 3–6 周）：把卖点做实（质量）

| # | 事项 | 说明 |
|---|---|---|
| 2.1 | 境内出口 | 为 gov.cn / 境内站引入中国大陆或香港出口代理（已有 PROXY_POOL 能力），解决用户 A 的超时；按"代理渲染"单独计费（参考 ScrapingBee 1/5/25 阶梯） |
| 2.2 | 知乎、飞书、小红书适配修复 | 知乎当前 0%；建立每日回归探针（每平台 5–10 个固定 URL），在 /admin 和公开状态页展示成功率 |
| 2.3 | 公开成功率面板 | 已在 TODOS（P2），现在升为 P1：按平台展示 7 日成功率和 p95，作为对外的信任证据和销售材料 |
| 2.4 | 失败不收费 + 阶梯计费 | 已部分实现，补齐文档并在响应头中标明本次计费层级 |

**完成标志：** 微信（带 key）≥ 95%、知乎 ≥ 80%、gov.cn ≥ 85%，且公开可见。

### Phase 3（第 4–10 周，与 Phase 2 并行）：分发

| # | 渠道 | 动作 |
|---|---|---|
| 3.1 | 官方 MCP Registry / Glama / mcp.so | 上架 MCP；README 主推远程 MCP（免安装） |
| 3.2 | Dify Marketplace 插件 | 做"微信/中文网页导入"插件——Dify 在国内用户多，这是对 Firecrawl 最直接的替代位 |
| 3.3 | n8n / Coze 节点、Claude Code / Cursor skill | 已有 skills 仓库，补齐上架 |
| 3.4 | 浏览器扩展（剪藏） | 把 bookmarklet 需求产品化：一键把当前页（含微信/知乎）转 Markdown 存到 Obsidian/剪贴板；本地优先提取以回应"经过别人服务器"的顾虑，失败时再走 API |
| 3.5 | 内容与社区 | V2EX 分享创造、少数派、Obsidian 中文论坛、掘金；写"微信文章转 Markdown 横评"（Jina/markdown.new/我们，附可复现结果）；英文侧 Show HN 以"Chinese web for AI agents"为切入点 |
| 3.6 | SEO/GEO | 按平台做落地页（"微信公众号转 Markdown""知乎转 Markdown""gov.cn 政策抓取 API"），落地页上直接可用 |

**完成标志：** 自然注册 ≥ 30/月，外部引荐占真人 PV ≥ 30%。

### Phase 4（第 2–3 月）：运营与可持续性

| # | 事项 | 说明 |
|---|---|---|
| 4.1 | D1 成本控制 | 429/401 访问日志抽样（如 1%）或单独 7 天保留；conversion_log 保留 30 天，聚合表长期保留 |
| 4.2 | 运营手册 | Paddle 退款/拒付/降级 runbook（TODOS P1）、滥用处理流程 |
| 4.3 | 指标体系 | 北极星指标：**每周付费用户的有效转换数**；漏斗：访问 → 注册 → 首次成功调用 → 7 日留存 → 付费；在 /admin 加入这些视图 |
| 4.4 | 合规边界 | 写清楚服务条款与 robots/版权立场，不承诺绕过登录墙；保留微信能力但限速，避免重蹈 wechat-article-exporter 关停的覆辙 |
| 4.5 | 平台风险预案 | Cloudflare 依赖预案（TODOS P2），至少准备 Browser Run 以外的渲染兜底 |

## 6. 明确不做（现阶段）

- Docker / 非 Cloudflare 部署（无需求信号）。
- 与 Firecrawl 比拼通用爬取、深度爬取功能。
- 新增海外平台适配器（除非付费用户提出）。
- 大规模广告投放。

## 7. 需要你决策的问题

1. **定位**：是否同意收窄到"中文互联网内容接口"，不再主打"any URL"？
2. **定价与支付**：人民币/美元双轨还是先只做美元（Paddle）？是否接受先做"充值包"而非订阅？
3. **境内出口**：是否愿意为大陆/香港代理付费（约 $50–200/月起），并据此开代理计费档？
4. **匿名大户**：对持续匿名调用的微信客户端，是"强制要求 key"（短期流量下降）还是"提示 + 降级"（温和）？
5. **浏览器扩展**：是否在 Q4 投入（约 1–2 周）？
